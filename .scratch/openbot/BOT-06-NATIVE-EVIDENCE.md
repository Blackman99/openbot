## Executable coverage

`apps/api/tests/postgres/bot-lifecycle-runtime.test.ts` registers 24 Vitest cases. Provider-state and permission matrices run multiple scenarios inside their named cases. The native setup applies real migrations, invokes the deployed runtime-role provisioner, and runs production services through `openbot_runtime`. Administrative access is used for observation, deterministic lock barriers, and mandatory-audit privilege fault injection. Basic capability evidence is a fixture, not an upstream provider transport result.

## CI handoff

The `postgres-bots` job in `.github/workflows/verify.yml` now has a named, separate sequential command for `bot-lifecycle-runtime.test.ts` after the identity, ACL, avatar, and version suites. The step requires a nonempty `TEST_BOT_DATABASE_URL` before launching Vitest, so a requested CI gate cannot silently succeed through missing-URL skips. Separate commands ensure each suite closes its pools before the next one rotates the fixed runtime-role password. BOT-05's separate copy command is owned by its independent integration and must remain in the combined job.
