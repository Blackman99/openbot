## Goal and source pins

Recover an interrupted model invocation using a new Run on the same Task, preserve its interrupted evidence, and fence the old claim from every later write. Provider execution can occur again; only one successful final result may become visible. High-availability database deployment, exactly-once provider execution and cross-region workers remain non-goals.

## New policy approved by root — not yet implemented

| Item | Recommended rule |
| --- | --- |
| Lease | **15,000 ms**, measured by PostgreSQL `clock_timestamp()` after relevant lock waits. Initial lease commits with the queued→running claim. Effective expiry is no later than the immutable attempt deadline. |
| Heartbeat / cancellation observation | **1,000 ms**, one serial loop per active Run, replacing/extending COL-07's existing observer rather than adding a second timer. Check once before provider I/O. Use finite DB connection/query/lock waits; a 1s cadence is not an unconditional outage SLA. |
| Renewal | Only the same current running Task/Run/token with an unexpired lease and deadline can renew. New expiry is `min(DB now + 15s, deadline)`. An expired lease cannot be renewed even if no reaper has acted yet. A failed/delayed renewal cannot authorize publication. |
| Recovery chain | `chainRootRunId` is the Run created by one unique user submission or new manual-retry transaction. Initial/manual Runs start ordinal1; all automatic successors inherit the chain. Same-key receipt replay never opens or resets a chain. |
| Shared automatic budget | Default **4 Runs total per chain**, including the first Run. `provider_retry`, `model_fallback` and `worker_recovery` share this persisted total; crash recovery additionally permits **at most 1** queued successor per chain. A queued successor consumes its slot even if cancelled or later denied at claim. Only a new authorized manual retry opens a new chain. |
| COL-10 / later limits | COL-10's proposed `maxRunsPerChain` (1..4, default4) and later hierarchical budgets may only reduce eligibility. Its per-model cap gates provider-failure retries; COL-11's separately authorized crash successor advances the existing model ordinal without replenishing that allowance. Thus an old Bot's ordinary provider failure still ends immediately, while its independently authorized one crash recovery can run within the shared total. No automatic reason resets model/fallback counters. |
| Normal deadline | Keep the hard attempt deadline independent of liveness. A Run whose hard deadline has already elapsed follows explicit `execution_timeout` termination, not a disguised provider retry or renewed lease. The deterministic crash-recovery witnesses expire the lease before the hard deadline. |
| Maintenance | New recommendation: one bounded reconciliation pass before reporting ready, then a non-overlapping 1s maintenance loop, at most10 candidates per pass. It must run while `runOnce` awaits a model, since the existing main Task loop is serial. One candidate uses one short transaction; transient failure leaves it for a later pass. |

No configured provider key retains the current `task_worker_unconfigured` behavior: no claiming or mutation of the queue. A healthy configured worker and available DB are required for reconciliation. On heartbeat DB error, abort the local invocation and discard unpublished buffers; do not invent a durable cancellation/interruption or use a cached lease to publish. Leave an uncertain claim for expiration/reconciliation rather than converting the observation error to a provider failure. Preserve COL-07 consumption of late promises/callback fencing and clean up both heartbeat and maintenance timers.

PostgreSQL documentation confirms `now()`/`CURRENT_TIMESTAMP` use transaction-start time, while `clock_timestamp()` advances during statements. Row locks serialize competing writers and consistent acquisition order avoids deadlocks. This supports the planned post-wait DB-clock checks; the concrete lease policy above is our design, not a PostgreSQL guarantee. Primary references: [time functions](https://www.postgresql.org/docs/17/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT), [explicit locking](https://www.postgresql.org/docs/17/explicit-locking.html), inspected 2026-09-05.

## New data and narrow interfaces

Proposed names/fields below are missing today. Final names and migration number belong to the accepted integration baseline; this document reserves no number and registers no predecessor placeholder.

| Proposed durable record / seam | Required invariant |
| --- | --- |
| `task_run_leases` | One row per claimed Run: Run/claim identity and optional process-instance UUID are immutable; `heartbeat_at`/`expires_at` are narrowly renewable. A separate table avoids weakening0022's immutable Run claim and legal-status-transition guard. Terminal/expired leases cannot reopen, change owner or be deleted to bypass fencing. |
| Shared attempt origin | Agreed fields: `chainRootRunId`, `chainAttemptOrdinal`, `origin: initial | manual_retry | provider_retry | model_fallback | worker_recovery`, `previousRunId`. Persist immutable provenance for each Run, with unique `(chainRootRunId, ordinal)` and at most one automatic successor for an exact previous Run. The initial/manual origin anchors a chain; automatic origins inherit it. These enum members are a coordination contract, not permission to implement unready tickets. |
| `task_run_recovery_receipts` | One immutable receipt per interrupted Run: Task/chain/source identity, interruption time, decision, successor Run ID or safe stop reason. Repeated startup/recovery returns that old decision without another audit/event/Run or a budget reset. If stopped, later policy/permission restoration does not silently revisit that receipt; an authorized new manual retry is available. |
| One attempt admission/writer | Borrow a caller-owned transaction. Derive current facts from the locked Task/latest Run, validate origin-specific authority/receipt/model plan and all shared budgets, then insert one queued successor and its provenance. COL-09 keeps its human command/replay contract; automatic work must not fabricate a human `task_retry_commands` key or claim a human click. COL-10 and COL-11 must not implement independent next-Run allocators. |
| Lease operations | Proposed `renewClaimLease(claim)` returns current ownership/expiry or a lost result; errors abort locally. Publication uses a borrowed-transaction lease check in the existing delta/finish path. Reconciliation consumes a persisted Run ID, not caller-supplied scope, actor, provider or event payload. |
| Safe read/UI additions | Add `worker_interrupted` to DB/API/BFF/SSE failure unions. An optional, bounded interruption/recovery receipt summary may expose old/new Run IDs, decision and safe stop reason; keep old stored v1 execution JSON readable. Extend the accepted partial reader to interrupted failed Runs; bodies remain in bounded detail reads, never in Task list/history rows or every state event. No public `/v1` route is added. |

Recommend a narrow heartbeat transaction that takes a **SELECT row lock on Run, then the lease row**, rechecks persisted current Task/Run/token and DB time, updates only lease metadata, and acquires no later resource/Task/provider locks. This is a subsequence of the mutation lock order and serializes renewal with cancellation/recovery without invoking0022's Task-locking Run UPDATE trigger. All execution mutations retain resource→root Task→Task→Run→lease ordering. Prove the shared order and post-wait expiry checks natively before accepting the helper; heartbeat must never become execution admission or a Run UPDATE bypass.

## Recovery transaction and authority

1. Observe at most10 current running candidates ordered by lease expiry/Run ID, without early `FOR UPDATE` or `SKIP LOCKED` on Run rows. Discover immutable scope; take **workspace → group → required Bot → conversation → root Task → selected Task → current Run → lease/provenance → provider scope**. Use COL-07's final root/ancestor ordering, and sample DB time after waits.
2. Recheck latest Run/token/state, lease, deadline and any prior recovery receipt. Fresh lease, terminal/completed/cancelled state, a newer attempt or an already-recorded decision yields no new work. Current cancellation wins over recovery. If the lease expired while the hard deadline remains live, prepare one `worker_interrupted` terminal transition; never extend the old claim or attach its token to the new Run.
3. Decide successor eligibility using the original execution human, current conversation rights, exact stored grant and grantor authority, pinned Bot version, current model-use rights and uncancelled ancestry. No administrator, Bot creator or worker service identity lends credentials. Authorization/model denial records an explicit terminal recovery stop reason and starts no new provider call. Budget/attempt-int exhaustion similarly stops. Temporary DB failure rolls the whole transaction back.
4. In the same transaction mark old Run/Task failed with `worker_interrupted`, freeze its committed partial, and append its typed failed state **while that old Run is still current**. If eligible, insert the new queued Run, immutable recovery/origin receipt and consumed budget, switch Task to queued and use the existing `appendQueuedRunState`. Persist mandatory safe interruption/recovery audits with explicit worker origin; no invented human command or second trigger. If ineligible, commit the stable no-successor receipt instead. All mandatory writes roll back together.
5. Only the normal queued claim transaction may admit credentials and invoke the provider after COMMIT. Recovery never calls a provider directly. Every delta/final/partial/usage/status writer must retain exact current attempt/token, live lease, cancellation/ancestry, deadline and authority guards, including fresh checks after mandatory-write waits. The stale invocation's late callback/result changes nothing, even before another worker notices its expiry.

Preserve Task/trigger/initial routing decision and Bot configuration. Reconstruct authorized current message revisions/tombstones within the original trigger creation-sequence horizon; do not revive captured prompts or add later messages. Preserve current `selectRunMemoryContribution`, `persistRunMemoryReferences` and `assertRunMemoryReferencesCurrent` seams when composing MEM; old authorization is not permission to reuse purged memory/source text. Partial draft text is never promoted into model context or a final answer.

Recovery retains the interrupted attempt's already-selected complete model binding. Today that equals the Task's pinned binding; when COL-10 introduces explicit fallback plans, recovery must carry that selected plan rather than revert to primary, reroute, skip to another fallback or reset per-model counters. The new attempt may admit a fresh connection/credential revision for that same permitted model. COL-10 owns provider retry/fallback classification and plans; COL-11 owns lease-loss classification and its immutable interruption receipt. Both must pass the same locked budget/attempt admission.

Existing failed/completed/cancelled Runs remain immutable. The old interrupted Run's provider, model, claim, start/deadline, usage and frozen partial cannot be overwritten by its successor. The new attempt starts with no inherited stream offsets or partial. Keep current Run inspectable and every older attempt paginatable through COL-09. After the old interruption state and new queued/running/delta sequence, only the winning successful Run appends one final Bot message; old partials remain separately labelled Interrupted.

## Upgrade and evidence gates

**Upgrade policy recommendation:** stop new claims, stop/drain all old workers, then additive migration preflight refuses atomically if any legacy Run is still running without a lease. Do not invent a heartbeat, treat an arbitrary old process as alive, reopen a terminal Run, or infer lost partial text from an expiring feed. Queued Runs and completed history survive; the first upgraded claim creates its lease. Existing initial/manual attempts can receive origin records only from retained Task/0022 human receipts; unexplainable provenance fails preflight. Resume new workers only after guards and restricted grants are installed. Recheck the final COL-07 drain policy; do not edit0017/0019/0022/0023 to force compatibility.
