# BOT-06 lifecycle contract

Built on accepted COL-02 `28ce290e994f769219eb16b17565eb589dc12e16`.

- Migration `0016_bot_lifecycle` follows unchanged 0015. `bots` owns lifecycle_state (active/archived/deleted), deleted_at, recovery_deadline and pre_deleted_state. Versions and avatars are retained. Runtime gets only the precise additional lifecycle column UPDATE privileges; no erasure privileges.
- BotSummary/BotDetail and historical GroupBotGrant.bot include required lifecycleState. It is current stable-identity state, separate from immutable configuration. `lockAuthorizedBot(...,'use')` denies every nonactive Bot, including group grantor admission. Existing direct conversation reads remain inspect-authorized; new direct conversations require use.
- `BotLifecycleService(pool, now?, graceMilliseconds=2592000000)` exports get/archive/restore/softDelete/undoDelete(actorUserId,workspaceId,botId). Every operation locks workspace then Bot and rereads current member/owner authority. Workspace or group administrators receive no bypass.
- GET `/api/v1/workspaces/:workspaceId/bots/:botId/lifecycle`; POST bodyless `/archive`, `/restore`, `/delete`, `/undo-delete`. Exact Origin required for POST; all receipts private/no-store. Response `{ lifecycle: { botId, workspaceId, state, deletedAt, recoveryDeadline, preDeletedState } }`; dates serialize to ISO strings/null.
- Archive/restore of deleted state conflicts. Repeated effective transitions return persisted state without audits. Repeated delete cannot extend its deadline. Undo restores the predeleted state, clears deletion fields, and rejects at or after its deadline. Transitions to active require the actual actor's current enabled exact-model verified Basic/provider-use admission. Undo of a nondeleted Bot is a no-op.
- Audits: bot.archived, bot.restored, bot.soft_deleted, bot.deletion_undone. Metadata contains workspaceId/botId/fromState/toState and deletion timestamps only on soft deletion; state and mandatory audit share a transaction.
- Errors: bot_forbidden 403, invalid_bot_request 400/413/415, bot_lifecycle_conflict 409, bot_recovery_expired 409, bot_model_unavailable 400 with existing allowlisted reason, bot_unavailable 503. Never report physical erasure.
- GET bots defaults to nondeleted visible Bots. `?view=deleted` includes only current member/owners' deleted Bots; `?view=usable` only active explicit direct ACL Bots. Detail/history permissions stay protected and independently enforced. Deleted copy source rejection is BOT-05's explicit guard; archived copy is inspect-authorized.
- The owner-only lifecycle page is reachable from Bot detail and the explicit deleted recovery view. Existing direct conversation receipts carry current `botLifecycleState`; historical direct and group pages label archived/deleted identity while preserving the stable Bot ID. Configuration restoration never changes lifecycle state.

Core evidence: actual API archive RED 404→200, restore RED 404→400 unavailable binding, delete RED 404→200; protected-history/new-use/group-marker regressions. Core targeted 77 API tests and API typecheck were green.
